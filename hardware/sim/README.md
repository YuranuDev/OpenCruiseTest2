# PWR-CTRL v2.4.1 SPICE検証キット（ngspice）

メイン基板（pwrctrl）の主要な動作をSPICEで確かめるためのテストベンチ一式です。
回路図（`pwrctrl.kicad_sch`）の定数をそのまま使っています。

## 1. 準備（Windows）
1. ngspiceを入れる
   - https://ngspice.sourceforge.io/download.html から `ngspice-4x_64.7z`（Windows 64bit版）をダウンロードする
   - `C:\Spice64` に展開する（`C:\Spice64\bin\ngspice_con.exe` ができればOK）
   - コマンドで使うのは `ngspice_con.exe` です（`ngspice.exe` はGUI版）
2. Pythonにライブラリを入れる：`pip install numpy matplotlib`（回路図を作り直す場合は `schemdraw` も）
3. 動作確認：`C:\Spice64\bin\ngspice_con.exe -v`

`run_all.py` は、`C:\Spice64\bin` と PATH から ngspice を自動で探します。別の場所に入れた場合は、環境変数 `NGSPICE` で指定してください。

## 2. 使い方
```
cd hardware\sim
python run_all.py          # 全ケースを実行（約40秒）
python run_all.py tb3      # 名前が tb3 で始まるケースだけ実行
```
- 結果は `out\report.html`（**回路図とグラフ付きのレポート。ブラウザで開く**）と `out\report.md`（判定表＋波形の画像）に出力されます。`out\*.png` は波形、`out\*.log` はngspiceのログ、`out\results.json` は判定結果のデータです
- `report.html` では、グラフの上でマウスを動かすと、その時刻の各波形の値が表示されます。点線は合否の基準、色の帯は試験シナリオの区間です
- グラフの内容（表示する波形・基準線・説明文）は `make_report.py` の `SPEC` で変えられます。`python make_report.py` だけでレポートを作り直せます
- 判定の意味：
  - **FAIL**：設計要求を満たしていない（直す必要がある）
  - **WARN**：余裕が少ない、または既知の制約（下の「4. 結果と所見」を参照）
- 1本だけ手で動かす場合：`ngspice_con -b tb1_power_sequence.cir`（`.meas` の結果が表示され、波形は `tb1_out.txt` に保存されます）
- 波形を対話的に見る場合：`ngspice_con tb1_power_sequence.cir` で起動し、`plot v(vsw) v(acc)` のように入力します

## 3. ファイル
| ファイル | 内容 |
|---|---|
| models.lib | 部品モデル（下の表） |
| tb1_power_sequence.cir | 電源シーケンス：ACC ON → MCU起動 → クランキング → ACC OFF → HOLD=L。`.param MCUFAIL=1` でマイコン停止（Hi-Z）を模擬する |
| tb2_supply_sweep.cir | 電源を0→30→0Vにゆっくり変化させる：ACC_SENSEの分圧、リレーが入る電圧、5Vが立ち上がる電圧、24Vジャンプスタート時のTVS電流 |
| tb3_kline.cir | K-Line：ファスト初期化、10400bpsのバイト、5ボー初期化。`.param PAR=0`（JP6のみ）／`1`（JP6＋JP7の並列駆動） |
| tb4_load_dump.cir | ロードダンプ（ISO 7637-2 パルス5a／5b）。`US`（ピーク電圧）、`RI`（内部抵抗）、`TD`（持続時間）、`CLAMP`（オルタネーター側のクランプ電圧）を変えられる |
| tb5_inrush.cir | リレーが閉じたときの突入電流（C1〜C3とDFR0946の入力コンデンサ）。`RH`／`LH`（ハーネスの抵抗とインダクタンス） |
| tb6_hold_time.cir | マイコンのピンがHi-Zになってからリレーが切れるまでの時間。C11、R2、U5のVT−、ZD1のモデルを変えられる |
| tb7_pulse_in.cir | パルス入力アダプター（PULSE-IN）：12V方形波、オープンコレクタ、3.3Vセンサー5kHz、40Vスパイク、JP2の使い方を確認 |
| tb8_buck_switching.cir | XL7015をスイッチング（150kHz）まで再現：出力リップル、負荷急変、インダクタのピーク電流、入力コンデンサのリップル電流。U1（マイコン用）とU8（センサー用）の2条件 |
| tb9_i2c.cir | I2C 400kHzの立ち上がり時間（30→70%）とLレベル。`CBUS`（バス容量）、`RPU`（プルアップ）、`RMOD`（モジュール側のプルアップ） |
| tb10_can.cir | CAN：TJA1042T/3＋PESD1CAN。通常の受信、CANH/CANLの14V・24V短絡、ISO 7637のパルス（−150V／＋100V、容量結合） |
| tb11_gpio.cir | XIAOのピンの誤配線保護：ポートに12V・25Vがつながったときのピン電流と3.3Vの上昇（`RSER`＝直列抵抗R80〜R84、`I3`＝3.3Vの消費）。あわせて921600bpsの送信の立ち上がり |
| schem/blocks.py | レポートに載せる「見やすい回路図」（b1〜b7.svg）を作る（schemdraw） |
| schem/kicad_crop.py | KiCadの回路図から各ブロックを切り出す（b1〜b7.png、レポートの「KiCad原本」）。回路図を変えたら実行する |
| run_all.py | 全ケースを実行し、判定してレポートを作る。ケースの追加や判定値の変更は、先頭の `CASES` を編集する |
| make_report.py、report_template.html | グラフ付きレポート（out\report.html）を作る |
| rd.py | 波形ファイルから、指定した時刻の値を表示する補助スクリプト |

### 定数を変えて試すには
- 各テストベンチ先頭の `.param` 行を書き換えるか、`run_all.py` の `CASES` に条件を追加します
- 回路の定数（抵抗値など）は、テストベンチ内の素子の行をそのまま書き換えてください（部品番号は回路図と同じです）

## 4. 結果と所見（基板v2.4.1、2026-11-11時点）
36ケース・161項目：**不合格（FAIL）0件、要注意（WARN）9件**。

### v2.4.1で直したこと（このSPICEの結果を受けて変更）
| # | テスト | 変更前（v2.4） | 変更 | 変更後（v2.4.1） |
|---|---|---|---|---|
| 1 | tb11 GPIOの誤配線 | 12Vで75mA流れ、XIAOの3.3Vが6.1Vに上がる（FAIL） | R80〜R84 100Ω→**1kΩ**（C21190） | 12Vで8mA、3.3Vは3.30Vのまま |
| 2 | tb9 I2C 400kHz | 2.2kΩで200pFのとき373ns（FAIL）。約160pFまで | R30/R31 2.2k→**1.2kΩ**（C22765） | 200pFで203ns。約295pFまで |
| 3 | tb8 U8の入力 | C40のリップル0.33A | C41 1µF→**10µF/50V X7R 1206**（C89632） | C40は0.27A（発熱で定格の約70%） |

### 変更による影響（確認済み）
| 対象 | 影響 | 評価・使い方の条件 |
|---|---|---|
| PCボタン（JP2） | なし | JP2はR84の前（IO_D10）につながるので、フォトカプラの電流は変わらない |
| パルス入力（PULSE-IN→D2/D3、tb7） | なし | 7条件すべて合格（デューティ比も同じ） |
| GPS UART（D6/D7） | 送信の立ち上がり235ns（ケーブル100pF） | 115200bpsなら問題なし。921600bpsは1ビットの22%で余裕が小さい→**460800bps以下を推奨** |
| AUXで1-Wire（D10） | マイコンがLにしたときの電圧0.58V（4.7kプルアップ） | **プルアップは4.7k以上**（2.2kでは1.0VになりDS18B20のL判定0.8Vを超える） |
| D6/D7を2本目のI2Cに使う場合 | 1kが直列に入る | プルアップ4.7k以上、100kHzで使う |
| マイコンのスリープ | 3.3Vの消費が8mA未満だと、12Vの誤配線で3.3Vが3.67Vまで上がる（要注意） | ファームの仕様にスリープはない。将来使う場合は3.3Vに数mAの負荷を足す |
| I2Cのセンサー基板のプルアップ | 合成で970Ω未満になると、Lレベルが0.4Vを超える（10k×6で0.41V、要注意） | **センサー基板のプルアップは合成で約5kΩ以上**（10kなら2枚まで。SparkFunのQwiic基板は2.2kのジャンパーを切る） |
| 5Vへプルアップしたセンサー基板 | バスのHレベルが下がる（10kで5Vへの場合、3.61V→3.48V） | 良い方向（ESP32-S3の絶対最大3.6V以内に入る） |
| I2Cの消費 | Lのとき1本あたり2.75mA（2.2kでは1.5mA） | XIAOの3.3Vに対して小さい |
| 突入電流（tb5） | F4を通るピーク6.0A→6.5A | PTCは切れない。I²tは1.17A²sでほぼ同じ |
| 部品の配置 | なし | 値だけの変更。フットプリント（0603／1206）と位置は同じ |

### 合格した主な値
- センサー用電源（U8・U9）：クランキング中も+5VSは5.23V、+3V3Sは3.28V。ロードダンプ（35V）でも止まらない
- DC-DC（tb8）：出力5.30V、リップル約25mV、負荷急変の最低4.98V。インダクタのピーク1.0A（SWPA8040S101MTの飽和電流は販売店の表記で1.15A。U8の負荷は0.7Aまで）
- CAN（tb10）：差動電圧2.08V。24V短絡でもU6のピンは最大41V（TJA1042の±58V以内）。ISOパルスはPESD1CANで−33V／＋31Vに抑えられる
- 突入電流（tb5）：ピーク92A、I²t 1.17A²s。D7は24.7A（IFSM 80A）、F4は6.5A
- クランキングでVSW 6.55V以上、+5V 4.76V以上。HOLD=Lから36msでリレーが切れ、マイコン停止時は7.9秒後に切れる（暗電流ゼロ）

## 5. モデルの精度
| 部品 | モデル | 精度・注意 |
|---|---|---|
| 1N4148W、MMBT3904 | 公開されている標準モデル | 良い |
| SS34、B5819W、LED | データシートの代表点に合わせたダイオードモデル | 順方向電圧は±50mV程度 |
| BZT52C3V6 | ツェナー（膝がなだらか／急峻の2種類） | **漏れ電流は個体差が大きい**。実物の測定値が最も確実 |
| SMAJ20A、SMAJ24A、SM8S20A | VBR（最小値）と、クランプ電圧から求めた直列抵抗 | 電圧は良い。**エネルギー耐量はモデル化していない**ため、データシートのディレーティング曲線と比べる |
| BSS138、2N7002K | Level-1 MOSFET（Vth、オン抵抗を合わせた） | スイッチ用途なら十分 |
| 74LVC1G17 | 動作モデル（ヒステリシス付きスイッチ、VT+／VT−を指定） | しきい値は使うデータシートの値に合わせる |
| G2RL-1A-E | コイル0.4H＋360Ω、動作9V／復帰1.2V、接点10mΩ | チャタリング（接点のバウンス）は扱わない |
| TJA1021 | 動作モデル（40Ω駆動、27msタイムアウト、30kプルアップ、受信しきい値0.5×VBAT） | レベルとタイムアウトは良い。**スルーレート（実物は数µs〜20µs）は再現しない** |
| XL7015 | ①平均化モデル（tb1/2/4）：5.30V、ドロップアウト1.2V、効率82%、UVLO 4.5V ②スイッチングモデル（tb8）：150kHzの電圧モードPWM＋PI制御 | ②の制御部は代わりの回路（メーカーのモデルがない）。リップルと電流は良いが、負荷急変の波形は目安 |
| AMS1117-3.3 | ドロップアウト1.1V、自己消費5mA | 目安 |
| TJA1042T/3 | 動作モデル（ドライバ20Ω、受信しきい値0.7V、入力25kΩ） | レベルは良い。スルーレートや保護回路の動作は再現しない |
| PESD1CAN | 逆直列のツェナー（VBR 27V、直列3.5Ω、26pF） | クランプ電圧はデータシートの代表点（1Aで36V）に合わせた |
| CANケーブル | LCの梯子（5区間、120Ω相当） | 反射の大まかな形だけ |
| ESP32-S3のピン | ESD保護ダイオード＋5pF。XIAOのLDOは電流を出すだけ（吸い込まない） | 実物のLDOも吸い込めないので、3.3Vの上昇は実際に起こる |
| DFR0946＋ノートPC | 定電力負荷67W＋入力コンデンサ440µF（推定値）、6V以下で停止 | 実機の入力容量と停止電圧は未確認 |
| XIAO ESP32S3 | 100mA＋WiFiのバースト350mA（2ms／20ms） | 目安 |

収束しやすくするため、条件分岐（if）はできるだけ `tanh()` を使ったなめらかな関数で表しています。新しく動作モデルを書く場合も同じ方法にしてください（ngspiceが時間刻みを細かくし続けて止まるのを防ぐため）。

## 6. KiCadのシミュレーターで使う場合（任意）
KiCad 9にはngspiceが組み込まれています。回路図の部品に `Sim.Library = sim/models.lib`、`Sim.Name = D1N4148` のようにモデルを割り当てれば、同じモデルを使えます。ただし、XIAOやDFR0946のような基板外の負荷は回路図に含まれないため、**このキットのテストベンチ（.cir）を使う方法をおすすめします**。LTspiceではngspice独自の書き方（`u()`、`pwr()`、SWモデル）がそのまま動かない場合があります。
